# Micronucleus+ ATtiny88 Pass26 — регистровый курсор и USB PHY (27.10.2026)

**Экспериментальный проект. Физически на ATtiny88 не испытывался.** Не
устанавливайте на единственную плату без ISP-программатора для восстановления.

## Результат воспроизводимой сборки

| Конфигурация | Pass25 | Pass26 | BOOT_AT | Резерв Flash | Flash приложения с учётом postscript |
|---|---:|---:|---|---:|---:|
| Без LED | 1216 Б | **1206 Б** | `0x1B40` | 1216 Б (19 страниц) | 6972 Б |
| LED active-high | 1230 Б | **1220 Б** | `0x1B00` | 1280 Б (20 страниц) | 6908 Б |
| LED active-low | 1228 Б | **1218 Б** | `0x1B00` | 1280 Б (20 страниц) | 6908 Б |

**USB PHY 498 → 492 байта.** Никаких лишних команд SELECT между линейными
чтениями и записями. Firmware и хост работают по протоколу **v5.5**;
`bcdDevice` соответственно `0x0550`, `0x0551`, `0x0552`.

## Постоянное распределение регистров

| Регистры AVR | Назначение |
|---|---|
| `r4:r5` | **Общий 16-битный байтовый курсор** Flash/EEPROM; в `r5.7` флаг EEPROM. READ8 увеличивает на 8, WRITE4 на 4 |
| `r6:r7` | 16-битный счётчик времени ожидания/опросов |
| `r8` | Количество оставшихся байт асинхронной записи EEPROM |
| `r10..r13` | Очередь четырёх байт EEPROM |
| `r3` | Операция SPM, отложенная до окна без USB |
| `r2` | Тип источника данных текущего USB-ответа: Flash/SRAM/EEPROM |
| `r23` | Внутри USB PHY — счётчик длины принятого пакета; позднее заново задаётся обработчиком CRC/TX |
| `X` (`r26:r27`) | В основном цикле — счётчик опроса, в генераторе USB-ответа — указатель записи пакета |
| `Y` (`r28:r29`) | В основном коде — база USB SRAM-контекста, внутри PHY — указатель приёма/передачи |
| `Z` (`r30:r31`) | Временный SPM/Flash/USB pointer, перезагружается по мере необходимости |

`X/Y/Z` **не удаётся закрепить за одной переменной на всём времени выполнения**:
V-USB уже использует их для битового приёма и выдачи. Сохранение пар через
PUSH/POP или SRAM в таком случае было бы дороже. Для долговременного состояния
выгоднее свободные регистры `r4:r5`, которые V-USB не портит.

## Сокращения от Pass25 (без LED)

1. **−4 байта в READ8.** Ранее каждый READ8 считывал 16-битный адрес из SETUP
   и умножал номер блока четырьмя (четыре сдвига). Теперь `MOVW r18,r4`,
   `MOVW r30,r4`, `ADIW r30,8`, `MOVW r4,r30` используют постоянный курсор.
2. **−2 байта в USB PHY.** Счётчик RX перенесён `r19 → r23`. Вместо старого
   `PUSH r19` стоит двухтактный `RJMP +0` без воздействия на регистры или
   флаги. Старый `POP r19` удалён. До начала выборки битов число тактов не
   изменилось; после обработки пакета управление возвращается на 2 такта
   раньше. Это всё ещё требует аппаратной проверки.
3. **−2 байта в RX PHY.** `EOR YH` + `SUBI YL` + `SBCI YH` заменены на
   `LDI YH,1` + `ADIW Y,22`. Адреса совпадают для всех 256 входных значений
   младшего указателя, суммарная длительность — 3 такта в обоих случаях.
4. **−2 байта в TX PHY.** `SUBI YL,22` + `SBCI YH,0` заменены на
   `SBIW Y,22`, 2 такта в обоих случаях. Проверены арифметика и флаг Z для
   всех 65 536 возможных 16-битных адресов.

Не изменены команда SPM, запрет стирания/записи загрузчика, формирование
CRC16 ответа, SETUP-диспетчер стандартных запросов и асинхронная EEPROM.

## Проверки

Запуск `sh verify.sh` собирает три варианта, создаёт ISP HEX/BIN без реального
доступа к устройству и исполняет набор офлайн-тестов:

- анализ реально скомпилированных AVR-инструкций USB PHY, семантики допустимых
  замен и адресов всех переходов;
- 13 824 сравнений стандартных USB-запросов;
- 675 сопоставлений реально сформированных USB-ответов с CRC;
- 780 проверок выбора адреса/стирания и защиты области загрузчика;
- 219 проверок регистрового указателя READ8 и сценариев EEPROM busy;
- 65 536 арифметических сравнений для TX pointer, 256 для RX pointer;
- реальные по опкодам проверки записи 64-байтовых страниц Flash и 16 EEPROM
  блоков, а также полные сценарии записи/чтения в модели хоста;
- проверки, что последовательные READ8 и WRITE4 **не вставляют лишние SELECT**,
  что после USB-ошибки курсор хоста сбрасывается, а при смене области —
  выбирается новая позиция.

Программная проверка **не доказывает** соответствие аппаратных временных
характеристик USB, особенно из-за исходного сдвига начала приёма из Pass25,
повторных пакетов и потерянных ACK. Не следует считать эти BIN/HEX
проверенным серийным загрузчиком.

## Порядок работы

```
sh verify.sh
python3 host/compact_programmer.py --identify
python3 host/compact_programmer.py firmware.hex --out patched.hex
```

Первые две команды не модифицируют устройство; `--identify` использует только
стандартный USB-дескриптор. Загрузка/прошивка по USB намеренно требует явных
флагов `--execute --i-have-isp-recovery` и отдельного аппаратного тестирования.

## Состав

- `variants/strict_usb_optimized/micronucleus_t88_pass26.S` — ASM v5.5.
- `variants/strict_usb_optimized/micronucleus_t88_pass25.S` — точная исходная
  контрольная версия для сравнения и анализа PHY.
- `host/compact_programmer.py` — хостовый код v5.5, регистровый курсор, чтение
  и проверка Flash/EEPROM, генератор RESET/postscript.
- `firmware/Pass26_{off,high,low}_body.bin` и соответствующие ISP образы —
  **экспериментальные, не для загрузки через установленный Micronucleus**.
- `build_release26.py`, `audit_phy26.py`, `tests26/`, `verify.sh` — инструменты
  воспроизведения, опкодные и модельные проверки.
- `PROTOCOL_v5_5_RU.md`, `PASS25_TO_PASS26.diff`, `verification_pass26.log`.
