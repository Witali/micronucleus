# Micronucleus+ ATtiny88 — компактный протокол v5.5 (Pass26)

**Экспериментальная реализация для ATtiny88, 16 МГц, V-USB Low-Speed.**
По сравнению с Pass25 v5.4 изменено поведение `READ8`; старую совместимость
не сохраняем. Хост выбирает профиль по `bcdDevice` стандартного USB-дескриптора.

## Формат адреса

`SELECT` и `SELECT+ERASE` принимают в `wIndex` 16-битный номер 4-байтового
блока. Бит 15: `0` = Flash, `1` = EEPROM. Младшие 15 бит — номер блока.
Физический байтовый адрес = `(wIndex & 0x7fff) * 4`.

Внутри AVR регистры **r4:r5** удерживают 16-битный *байтовый* курсор;
бит 15 продолжает обозначать EEPROM. Курсор автоматически продвигается по
мере чтения и записи. После смены области памяти, позиционирования назад или
ошибки USB следует отправить новый `SELECT`.

| Vendor request (EP0) | wValue | wIndex | USB data | Действие |
|---|---|---|---|---|
| `0x01 SELECT` | игнорируется | адрес блока / память | нет | Установить общий курсор |
| `0x02 SELECT+ERASE` | игнорируется | выровненный по странице Flash адрес блока | нет | Установить адрес + отложенное стирание 64-Б страницы Flash |
| `0x03 WRITE4` | первые 2 байта | последние 2 байта | нет | Записать 4 байта, курсор `+4` |
| `0xB0 READ8` | игнорируется | игнорируется | ровно 8 байт IN | Прочитать 8 байт, курсор `+8` |
| `0x04 RUN` | игнорируется | игнорируется | нет | Запуск приложения |

На шине USB Low-Speed каждый физический DATA-пакет содержит максимум 8 байт.
`READ8` — один Control Transfer с 8-байтовой фазой IN; `WRITE4` передаёт данные
непосредственно через `wValue/wIndex` восьмибайтового SETUP.

### Пример чтения

1. `SELECT` с `wIndex=0x0020` — Flash, байтовый адрес `0x0080`.
2. `READ8` → байты `0x0080..0x0087`, курсор `0x0088`.
3. `READ8` → байты `0x0088..0x008F`, курсор `0x0090`.
4. `READ8` → байты `0x0090..0x0097` и т. д., **без других SELECT**.

`SELECT(0x8002)` начинает чтение EEPROM с байтового адреса `8`; далее
`READ8` считывает `8..15`, затем `16..23`, пока хост не остановится на 64 байтах.

### Пример записи Flash

1. `SELECT+ERASE` c индексом страницы (кратно 16 блокам = 64 байтам).
2. После паузы SPM выполнить 16 последовательных `WRITE4` на 64 байта.
3. Подождать SPM, затем использовать `SELECT` для переноса курсора к началу
   страницы и восемь `READ8` для проверки без повторной установки адреса.

### Запись EEPROM

Четыре байта `WRITE4` ставятся в очередь из регистров `r10..r13`, а аппаратные
байтовые записи выполняются асинхронно между периодами USB-опроса. **Нельзя
посылать следующий `WRITE4`, пока предыдущая очередь ещё активна.**

Штатная хостовая утилита предлагает проверяемую по блокам запись. Есть
экспериментальная `program_eeprom_stream()` с одним `SELECT` на весь EEPROM;
она выдерживает программную паузу >=50 мс после каждого блока и обязательно
перечитывает весь EEPROM. Эта пауза не является подтверждённым сигналом READY;
режим требует аппаратной проверки и не включён по умолчанию.

## Состояние и ограничения

- У Flash и EEPROM **общий** курсор. Чтение между незаконченными операциями
  записи Flash или EEPROM запрещено на стороне хоста: оно может изменить
  позицию записи. Для нового участка всегда используйте `SELECT`.
- EEPROM `READ8` при активной очереди или EEPE возвращает пустой ответ и **не
  сдвигает** курсор. Хост сбрасывает своё представление о курсоре при коротком
  ответе и повторно позиционируется.
- При USB-ошибке/тайм-ауте хост не должен слепо повторять `WRITE4`: необходимо
  восстановить адрес новым `SELECT` и проверить Flash/EEPROM. Как и в Pass25,
  протокол не обеспечивает транзакционный commit по подтверждённому ACK.
- Проверка границы Flash при **стирании/записи** в самом AVR сохранена. Чтение
  Flash, включая область загрузчика, разрешено.
- RESET вектора приложения и postscript готовит **хост**. Сбой питания при
  стирании страницы RESET может потребовать ISP-восстановления.
- Стандартные USB-запросы `GET_DESCRIPTOR`, `SET_ADDRESS`, `GET_STATUS`,
  `GET_CONFIGURATION`, `SET_CONFIGURATION`, `GET_INTERFACE` сохранены.
- **Новые bcdDevice**: `0x0550` (без LED, BOOT_AT `0x1B40`, 1206 байт),
  `0x0551` (LED active-high, BOOT_AT `0x1B00`, 1220 байт),
  `0x0552` (LED active-low, BOOT_AT `0x1B00`, 1218 байт).
- EEPROM 64 байта; Flash 8192 байта, физическая страница Flash 64 байта.
- USB PHY переработан без изменения числа тактов на проверенных участках, но
  **физическая USB-совместимость Pass26 не проверена**. Имеется унаследованная
  потенциальная проблема раннего ACK для непустого DATA до CRC16.
