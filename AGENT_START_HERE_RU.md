# Передача проекта следующему агенту — начать здесь

## 1. Точная задача и текущий результат

Продолжить **Micronucleus+ / ATtiny88, compact strict USB**, а не соседний
Block64. Пользователь стремится сократить прошивку до **одного килобайта**,
одновременно сохранив USB Low-Speed, запись/чтение Flash и EEPROM и базовую
защиту области самого загрузчика. В собственном протоколе старые версии
не поддерживаем; переносим организацию операций/адресов/векторов на компьютер.

**Последний законченный срез:** Pass26, протокол **v5.5**, датирован 2026-10-27.
ASM: `variants/strict_usb_optimized/micronucleus_t88_pass26.S`.
Хост: `host/compact_programmer.py`; локальные тесты: `sh verify.sh`.
Образ без LED: 1206 Б, PHY 492 Б, BOOT_AT=0x1B40 (19 страниц), Flash приложения
6972 Б с 4-Б postscript, VID:PID=`16D0:0753`, bcdDevice=`0550`.
Варианты LED: 1220 Б/1218 Б, BOOT_AT=0x1B00, bcdDevice=`0551`/`0552`.
Сверяй с `firmware/manifest.json`, а не только с этим текстом.

## 2. Команды первого запуска (ничего не прошивают)

```sh
sh verify.sh
python3 host/compact_programmer.py --help
python3 -m py_compile host/compact_programmer.py
sha256sum -c MANIFEST_SHA256.txt
```

В `firmware/SHA256SUMS.txt` находятся SHA-256 релизных образов; сравни их с
результатом `sh verify.sh`. Три `Pass26_*_body.bin` — только тело загрузчика.
`Pass26_*_ISP_FRESH_EXPERIMENTAL.hex` и `*_ISP_FRESH_8192.bin` — полные
первичные ISP-образы, которые могут стереть приложение. На реальную плату
пока **ничего не записывай**.

## 3. Что изменено относительно Pass25

- Регистры `r4:r5` теперь **постоянный байтовый курсор Flash/EEPROM**.
  Команда SELECT принимает 16-битный индекс **четырёхбайтового** блока;
  бит 15 означает EEPROM. READ8 увеличивает курсор на 8; WRITE4 — на 4.
  Между последовательными операциями новый SELECT не нужен.
- В RX USB PHY счётчик длины пакета перенесён `r19 → r23`. PUSH r19 заменён
  двухтактным `RJMP .+0`, POP r19 удалён; сам битовый RX семплируется в
  исходных тактах, но время выхода из обработчика стало на 2 такта короче.
- 16-битные вычисления указателей в PHY заменены эквивалентными `ADIW` и
  `SBIW` при сохранении выбранных живых флагов и длительности.
- Собственные команды: `SELECT=0x01`, `SELECT+ERASE=0x02`, `WRITE4=0x03`,
  `RUN=0x04`, `READ8=0xB0`. Стандартные USB-запросы сохранены.
- Различение варианта происходит по стандартному `bcdDevice` USB-дескриптора,
  таблица размещения/векторов и подготовка пользовательского HEX — на ПК.
- Сохранены проверка границы SPM и запрет записи/стирания области загрузчика.

Точные семантические изменения: `PASS25_TO_PASS26.diff`, `README_PASS26_RU.md`,
`PROTOCOL_v5_5_RU.md`, `docs/REGISTERS_AND_CONTRACTS_RU.md`.

## 4. Обязательные ограничения

- **Ни Pass25, ни Pass26 не проверены на реальном USB с новой компоновкой.**
- Pass25 начал первичный поиск USB SYNC на 4 такта раньше; модель нашла
  различия в поздних фазах. Pass26 сохраняет этот риск.
- Исторический PHY потенциально подтверждает непустой DATA-пакет ACK **до**
  полной проверки CRC16. Нет оснований считать загрузчик USB-IF compliant.
- Асинхронная запись EEPROM и индексный курсор — разные состояния:
  между незавершёнными записями нельзя произвольно запускать READ8/WRITE4.
- Любой потерянный ACK/USB тайм-аут оставляет неопределённость, произошла ли
  запись и сдвинулся ли курсор; **проверка и ресинхронизация на хосте обязательны**.
- Обрыв питания при стирании страницы с RESET может разрушить запуск, даже
  если компьютер подготовил правильный RESET и postscript.
- Нет аппаратной защиты загрузчика от самостоятельного SPM: защита логическая.
- Нельзя заменять циклы NRZI/bit stuffing на меньшие по коду без
  проверки точного бюджета тактов на всех путях.

## 5. План следующей итерации

1. Воспроизведи SHA/размеры и тесты; держи Pass26 неизменной контрольной
   версией. Любые изменения — новый Pass27 или отдельная экспериментальная
   ветка и diff.
2. Измеряй размер при `0x1B40` и `0x1C00`: второй адрес упрощает проверки,
   но пока 1202 байта из доступных 1024; **не хватает 178 байт**.
3. Начни с компактного EP0, диспетчера USB-запросов, повторных загрузок
   указателей, общих хвостов, регистров и подпрограмм (см. план в `docs/`).
4. Для каждого кандидата собери все LED-профили; проверь размеры, корректную
   адресацию, отсутствие AVR relocations и все тесты USB/NVM.
5. Отдельно исследуй USB приём/ранний ACK: подтверждать корректность по
   факту сборки недостаточно. Перед реальным испытанием нужен ISP recovery.
