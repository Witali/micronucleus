# Следующие инженерные задачи, по приоритету

## Цель: 1024 байта

Pass26 без LED при BOOT_AT=`0x1C00` компилируется в **1202 байта** из
возможных 1024. Чтобы реально разместиться в 16 страницах, требуется
сэкономить **178 байт**; при текущем BOOT_AT=`0x1B40` занимает 1206 из
1216 байт (19 страниц). Не обещайте достижение 1 КиБ без сборки и тестов.

## P0 — воспроизводимость / корректность

- `sh verify.sh`; сравнить `firmware/manifest.json` и SHA.
- Не менять эталон `Pass26` без дубликата нового кандидата и diff.
- Зафиксировать все изменения флагов AVR (особенно Z/C), X/Y/Z и точные
  циклы приёмника/передатчика в отдельном аудит-скрипте.
- Изучить поддержку повторных USB-транзакций, IN ACK, обработку раннего ACK
  до CRC16; не вводить небезопасные ускорения на основании UDP-подобной
  модели вместо настоящего USB Control Transfer.

## P1 — уменьшение non-PHY

- Инвентаризировать по символам кодовые области: начальная инициализация,
  контроль USB-сессии, стандартные дескрипторы, выбор адреса, Flash SPM,
  EEPROM, общий ответ, переход в приложение.
- Ищи повторные `LDI`/`STD`, общие хвосты для короткого/пустого ответа,
  одинаковые проверки/запись указателей и циклы в не-критичных путях.
- Перед любым объединением ветвей проверить близость по AVR BRxx (±64 слова)
  и размер `RCALL/RJMP`, включая изменение размещения 0x1B40 → 0x1C00.
- Проверить, что хост может взять на себя геометрию, выравнивание страниц
  и подготовку RESET без удаления **проверки записи** у загрузчика.

## P2 — оптимизация PHY только при доказанных тактах

- Рассматривать общие RX/TX хвосты и предварительные этапы, но сохранять
  NRZI, stuffed bit detection, EOP, ACK/NAK и корректные периоды семплирования.
- Сравнивать машинные слова и тайминги для каждого пути RX/TX, включая
  поздние фазы SYNC, и не путать число байтов Flash с временем обработки.
- Учесть, что глобальные X/Y/Z живут в разных фазах; уже закреплённые
  `r4:r5` и `r6:r7` дают экономию без повторного PUSH/POP.

## P3 — аппаратная проверка отдельно

- Только при наличии ISP восстановления + резервных копий.
- Логический USB анализатор/осциллограф, плохие CRC, короткие пакеты,
  потерянный ACK, хабы, повторные пакеты, паузы SPM.
- Не использовать Pass26 на единственной рабочей плате.

## Критерии принятия нового Pass

- Повторяемый размер трёх сборок + зафиксированные SHA, новый bcdDevice.
- Нет AVR linker relocations, app boundary и postscript корректны.
- Все штатные стандартные USB запросы сохраняются.
- Тесты PHY/NVM/host проходят на реально исполняемых опкодах.
- Любой риск электрической USB совместимости явно документирован.
