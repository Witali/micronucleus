# Full no-LED firmware audit, 2026-10-30

The composed receiver is 1518 bytes at 0x1A00, SHA256
`bc4faea264abcd7382f3dca31824fd44536838e71337471db91fbe3d57a9f818`.
It advertises unknown profile FFFF. No board was accessed or programmed.

All 42 selected-image groups were executed against these exact bytes: one
exhaustive 39-group run, followed by the three newly added checks. There are
39 passing groups and three failing groups. The ignored aggregate report is
`build/variants/combined_rx/full-firmware-audit.json`; its provenance distinguishes
the original run from the separately executed additions.

These are actual failures, not expected-failure allowances. Incoming numeric
DATA CRC16 checking/storage remains the sole waiver. In the older conservative
crossover stress corpus, fourteen CRC-storage-only differences are covered by
that waiver; discarded payload-bearing packets are not.

## Passing coverage

The selected checks include instruction arithmetic/cycles, standard requests,
6048 OUT response timings, 576 STALL followups, retry/ACK ownership, reset and
poisoned startup, sequential Flash writes/reads, token CRC5/address/endpoint,
full packet framing and corrupted stuffing. The complete source waveform has
21-clock SE0 and 11-clock driven J; the added 975-case EOP check passes.
The explicit selected-image NVM guard passes 512 cases.

Independent checks also pass host packing, failure/readback handling, offline
EEPROM planning and its gate, emitted Flash guards, and the restored legacy ACK
opcode/waveform regressions. The default NVM command still builds three distinct
LED modes for 1536 cases. LED sizes are not the optimization target; the composed
active-high build overflows 0x1A00 by two bytes and is not an admitted image.
The recognized strict-source release roundtrip passed separately at 1368 bytes
and 0x1A40; that different receiver is not a qualification of the composed image.

## Corrections made to the test suite

The selected verifier now includes the omitted TX-EOP and NVM checks and the
new physically motivated centered-crossover regression. An explicit NVM artifact
is tested once, without silently replacing requested LED modes with one image.
The legacy ACK executor implements ANDI; its waveform adapter recognizes the
BRTS/BRTC disassembler aliases. Direct post-framing fixtures provide captured
recovery J. These test repairs do not change firmware bytes or weaken an oracle.

## Repair candidates and loop measurements

Two independently validated larger repairs are preserved as
[non-default patches](usb-rx-repair/README.md). They have not been applied to the
active receiver while the compact alternatives and remaining failures are open.

| Candidate | Flash effect | Result |
| --- | ---: | --- |
| Private bit7 byte store | +30 bytes | Fixes all twenty FF framing cases with no newly failing identities in its completed checks. |
| Private odd5 crossover recovery | +34 bytes | Fixes all fourteen centered, zero-jitter failures; normal sampling remains unchanged. |
| Conditional bit7 counter retime | +4 bytes | Fixes twenty FF cases but adds three legal DATA1 tail failures; rejected. |
| Counted wait-for-K family | -12 to -16 bytes | Small smoke/jitter subsets improve, but paired-token tests expose corrupted SETUP fields and lost minimum-gap exchanges; rejected. |
| Two-word SPM load loop using the existing NAK scratch seed | -2 bytes | Passes 96 writes, 26 reads and 99 gap cases, but fails the expanded ACK-tail followup matrix; rejected. |
| Counted SETUP shadow copy | No saving | Current six LDDs are 12 bytes/12 clocks. Two straightforward loops for the split destination registers need 24 bytes/44 clocks. This is static instruction accounting, not a compiled admission result. |
| Four-clock terminal EOP polling kernel | 52 bytes, standalone | Short-EOP/crossover signal tests pass, but packet integration still needs exact final-one limits and continuous early observations. It is not a firmware fix. |

The word-load loop uses NAK's leading bits 01 as a two-iteration shift counter.
It adds seven post-ACK clocks. The expanded minimum-gap test catches the next
SETUP being lost despite both old words reaching the hardware buffer correctly.
Reducing source repetition or passing the smaller gap fixture is insufficient.

The counted SYNC loop increases probe spacing from two to five clocks. Adjusting
the fractional divider and a delay can fix the known 180-case subset while still
corrupting another valid request. No such calibration was promoted.

All current failures and admission gates remain visible. The active firmware
remains 1518 bytes, 238 bytes above the 1280-byte objective. Digital tests do not
constitute physical or complete electrical USB certification.
