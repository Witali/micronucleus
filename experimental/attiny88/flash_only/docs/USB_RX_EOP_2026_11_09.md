# Unified receive/EOP work, 2026-11-09

The objective is a smaller complete receiver with the remaining legal DATA
and SYNC failures repaired. The starting body at commit 6875f32 is 1768 bytes
at 0x1900; the separate ACK variant is 1936 bytes at 0x1800. No additional
USB waiver, CRC table, hardware installation or recognized profile is added.

## Share the terminal rejection tail

The early final-CRC qualifier and ordinary final-tail qualifier both reject
through the same two-clock RJMP with no publication or state effects. Alias
their two labels, move the early qualifier after that shared jump, and place
the stuff7 tail before bit6 to retain the short branch ranges. The instruction
graph and all related GPIO/call/branch paths keep the same clocks.

| Variant | Bytes before→after | After SHA256 |
| --- | ---: | --- |
| Default at 0x1900 | 1768→1766 | `9459888f75d3c98fb636cabb910ae401f69f858bc68dfc4d1eb1eb02a89a2f4e` |
| ACK at 0x1800 | 1936→1934 | `03393220e9d0b5da9c6c554d0f301b3ac1abe017fe2f00d59a61da7cfca77e4c` |

The artifact-driven `tools/compare_eop_reject.py` validates ELF/body/symbols,
then compares every reachable emitted instruction and direct successor from
the named code roots. Conditional outcomes, skips, calls and continuations
are included. Ordinary words/immediates match exactly; only relocated direct
targets differ. The only many-to-one mapping is the intended rejection jump.
Default: 864 instructions and 1063 successor edges; ACK: 948 and 1177.
Both remove exactly two bytes and add zero clocks to corresponding paths.
This is code-graph equivalence, not full USB qualification.

The final maintained default body independently passes 450 legal plus 1048
negative terminal-CRC classes, 756 seven-one bounds, 6185 DATA framing cases
and 512 explicit-image NVM guards. Paired private checks also retain context
restoration and the exact same 48/252 inherited truncated-ACK recovery
failures. The ACK pair passes seven selected groups, including 252 prefix
recoveries, 2484 legal ACK crossovers and 1008 fractional tails. No failed
oracle was weakened or turned into an expected pass.

```sh
python3 tools/compare_eop_reject.py --before before/artifact.json --after after/artifact.json --output build/eop-reject-proof.json
```

The bit6-to-stuff6 short branch reaches its positive 63-word limit in this
layout. Broader compositions must be linked and rechecked; source movement
alone does not establish a valid AVR branch or timing schedule.

## Remaining work

The two-byte change does not repair the existing DATA/SYNC findings. A
separate continuous three-phase symbol decoder has paired observations,
mandatory-symbol handling and shared crossover/EOP entries in 312 bytes.
Its initial emitted-word matrix passes 9359 component cases, but it lacks
true payload correction/publication, byte count, final framing and qualified
SYNC composition. It is not a replacement bootloader or a full-image saving.

An ordinary current DATA witness observes a legal short SE0 at clock 120.5
and valid K at its confirmation at 124.5, then rejects it unconditionally.
Phase-typed recovery and a cohesive replacement are being investigated
against that actual state, not an injected ideal phase. The independent
312-byte core's passing centered-entry controls do not qualify acquisition.

Private frozen sources, bodies, graph proofs and failure traces are retained
under `validation/unified-rx-eop-nov09/`. A loop or new decoder may replace
linear code only after its physical sampling, short/fractional EOP, stuffing,
next-packet recovery, ownership and response deadlines pass unchanged checks.

## ACK correctness baseline

Correctness takes priority over size. The verification default now selects
the existing `variants/ack_terminal` reader at 0x1800, with a 1934-byte body and SHA256
`03393220e9d0b5da9c6c554d0f301b3ac1abe017fe2f00d59a61da7cfca77e4c`.
It fixes all 48 failures among the smaller receiver's 252 truncated-ACK
followups. A genuine six-bit ACK prefix previously remained in reception
until clock 562, past the following SETUP's physical SOP at 181.472. This
reader rejects at 166, cancels at 172 without retiring the cached DATA, and
receives the next SETUP correctly. All 41148 premature PID prefixes, 162
empty PIDs and 1485 minimum-gap ACK-to-next-SETUP/WRITE4 exchanges pass.

The original full exhaustive run on immutable body/ELF/symbols completed all
65 groups in 1122 seconds: 59 pass and 6 fail. Its reports and frozen fixtures
are preserved; later changes do not rewrite that historical result. Five
groups expose mandatory defects:

| Group | Failing case records / tested cases |
| --- | ---: |
| Adjacent transients authorize an overlong token before its real EOP | 12/54; 5454 single-pulse and 54 pristine controls pass |
| Asymmetric SE0 DATA crossings | 120/2484 |
| Transient SE1 DATA crossings | 63/2486 |
| Mixed payload preservation | 69/981 |
| SYNC crossings | 144/1080; 54 clean controls pass |

The sixth strict failure is 1344 incoming NAK/STALL cases whose old fixture
required internal buffer publication. USB 2.0 section 8.4.5 forbids those host handshakes.
After reviewing the primary specification, retain all 1344 cases as negative
effect checks with a pending IN reply/address; publication itself is optional.
The corrected matrix passes on both current images: 9072 DATA-tail cases,
14784 valid-host jitter cases and 1344 forbidden handshakes. No mandatory
DATA/token/SYNC expectation changes.

The newly added fractional-DATA gate also passes 9720 cases on each image,
half with 670 ns EOP. It checks full payload/count, ownership and physical ACK
responses of 43.512743628..62.766743372 clocks. Together these separately frozen
checks cover the current 66 groups: 61 pass, 5 mandatory groups remain failing.
This is a composed inventory from the full original run plus the two reviewed
test updates, not a claim of a new single all-green run or complete USB
qualification. The sole numeric incoming-DATA-CRC16 waiver remains unchanged.

## Rejected loop and partial recovery experiments

A counted phase loop saves two bytes but fails 350/450 legal final-CRC cases.
Its changed SECOND/cold-confirmation clocks miss a 10.72-clock EOP and can
place ACK at 69.3457 clocks beyond a 69.0625 bound. It is not selected.
Cold initialization/copy loops did not provide a smaller implementation;
CRC, payload copying and disconnect delay already use loops.

A separate phase-typed ordinary-SE0 recovery body of 1810 bytes at 0x18C0 passes all 2484
FF-stream asymmetric cases, previously 120 failures. Broader 981-case payload
testing rejects it: its EF next-stuffed-transition witness ACKs a wrong
payload, where the control rejected the packet. The returned differential
line does not prove whether the erasure belonged to the current DATA zero or
the next transition. This candidate and its 1974-byte ACK composition are
rejected and are not maintained firmware. The latter full run was stopped
after the regression was established; it is not a completed gate.

The 312-byte symbol core also fails 475/2592 independent fractional DATA-ending
cases despite its earlier 9359 component passes. An 11-clock FIRST gap can
miss the entire 10.72-clock EOP while SECOND sees zero. A recovered FIRST-only
zero can likewise alias a legal crossover. Correct publication schedules
alone do not repair that missing observation. Work therefore continues on a
receiver with line/run state and additional timed observations, and on the
retimed V-USB PLL alternative. Neither is a qualified full replacement yet.
